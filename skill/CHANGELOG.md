### 顺带修好的流水线缺陷（都是实测暴露的）

1. **策展条目的修订台账无处存放**。`data/glossary.json` 是派生产物：世界观渲染会先把它重置成只含
   wiki 抓来的 39 条，策展条目随后被重新并入；而生成器又把 curated 内容写回 data ——
   于是下一轮读到的 data 必然等于 curated 内容，**任何「比对上一轮」的留痕逻辑都恒为无差异**。
   结论：台账必须存在源文件里。现 `curated-terms.json` 增加 `history` 字段承载台账，
   生成器只负责逐轮带进 `data/`；`term:term-40` 已补记两条真实修订（0.1.2、0.1.4）。
2. **`$existing += ...` 在循环里重建数组**，导致后续循环读不到刚追加的元素（`$existing.Count` 停在 39）。
   改用 `ArrayList` + `.Add()`，并在 `ConvertTo-Json` 前 `.ToArray()`。
3. **`Set-Content` 正则替换改坏过脚本**：吞掉一行 `foreach (...) {`，
   使 `continue` 落在循环外、脚本静默跑一半就退出（**exit=0**）。已修复并写入踩坑清单。
4. `SKILL.md` 新增「〔摘要由正文推导〕条目必须声明」规范（配合 0.1.3 的方案 A）。

### 🔴 修了什么：一个把 13 个真任务当垃圾丢掉的准入规则

**症状**：4.6 版本 wiki 上有 5 个主线任务，本 Skill 只收录了 1 个（`剧场及其复象`）。

**根因**：主线准入规则写错了 ——

```powershell
# 0.1.2 及更早（错误）
$isMain = ($hasGist -or ($description.Length -gt 20 -and -not $series))
```

`-not $series` 让后半段对**任何属于系列的任务**直接失效，整个表达式退化成
「**wiki 是否已填「剧情梗概」**」。而 4.6 的 `月升之前，与兽共舞` 系列 5 个任务里，
有 4 个的 `剧情梗概` 字段是空的（新版本 wiki 还没补写），于是被当成「非主线」整批丢弃。
`剧场及其复象` 能留下，纯粹只因为它的梗概**已经被人填了 520 字**。

**被误伤的完整名单（13 个，全是 `任务类型=开拓任务`，全都有 7–27KB 剧情正文）**：
- 4.6 `月升之前，与兽共舞`：知识、沉默、擦肩而过 / 无私的基因 / 人造天堂，脑髓地狱 / 狩猎愉快（**4 个**）
- 4.0 `欢迎来到乐园`：幻造艺术的基本原理 / 机械复制时代的艺术作品（2 个）
- 1.0 `今天是昨天的明天`：模拟宇宙•始发测试（1 个）
- 1.0 `宇宙均衡`：「均衡」的试炼 • 壹~陆（6 个）

**修法**：改用 wiki 的**权威字段**判定，不再用编辑进度信号做准入 ——

```powershell
# 0.1.3 起（正确）
$isMain = ($m.type -eq '开拓任务')   # 实测 217/217 全部为该值
# 再要求「任务地区能归入已知章节」
```

**影响**：收录数 **204 → 217**（章节目录：序幕 8→9 / 雅利洛 24→28 / 罗浮 16→18 /
匹诺康尼 45 / 翁法罗斯 66 / 二相乐园 45→**51**）；`entry_count` **451 → 464**。

### 方案 A：wiki 未填梗概时，摘要由正文推导

对上述 13 个任务（及今后同类情况），不再空着，而是从任务正文推导摘要：

- 新字段 `summary_source`：`wiki-gist` | `story-derived` | `wiki-description`
- 新字段 `provisional: true` 标记临时摘要
- 摘要格式：`（wiki 未填梗概，以下由任务正文推导）流程：<流程链>` + 正文旁白/场景节选（不足时用台词补）
- `references/*.md` 里这类条目的标题渲染为 **概要〔摘要由正文推导，wiki 未填梗概〕**
- 分片 front-matter 顶部加醒目提示，`confidence` 注明有几个临时摘要
- `key_points` 对这类条目**保持为空**（不凭空补关键节点）
- `SKILL.md` 第 5 节新增规范：引用这类条目必须声明「wiki 还没写梗概，以下是依正文推导的」

### 连带修正：账目口径

0.1.2 的 `chapter-index.md` 写着「204 = 主线，已入库；13 = 非主线，故不入库」——
**这是错的**：204 实际度量的是「wiki 编辑填了多少梗概」，13 也不是非主线。
现改为按权威字段口径统计，并显式写明本次修正与旧口径的错误原因。

### 教训（已写入 `distill/README.md`）

1. **不要用启发式规则覆盖权威字段**。wiki 已经用 `任务类型` 表明了是不是开拓任务，
   我却又写了一条启发式判断去"再判断一次"，结果把范围判断变成了编辑进度判断。
2. **覆盖率类数字要说明它到底在度量什么**。「204」算得没错，但含义错了 ——
   而且第一轮测试还把它当成"账目自洽"的证据核对过。**算术自洽 ≠ 语义正确**。
3. **新版本内容必须单独抽验**。这个 bug 恰好只在「wiki 还没补写梗概」的新内容上暴露，
   老章节因为梗概齐全全部幸免，所以 7/7 冒烟测试一条都没碰到。

- 冲突待复核：`term:term-40` 的举办周期（见 `pending-review.md`）

### 修了什么（逐条对应测试发现）

1. **[blocker] `谐乐大典` 把来源冲突写成定论。**
   原 `key_points` 断言「周期：每个琥珀纪一次」，但**同一批来源**里 wiki「匹诺康尼」页写的是
   「**一年一度**的谐乐大典的举行地」（`raw/worldview/匹诺康尼.wikitext` L504），
   而游戏内广播台词（开拓任务《长日入夜行》）说「每个琥珀纪仅举办一次」。
   **来源自身就矛盾，我却择一当定论**，违反本 Skill「冲突不覆盖」协议。
   现改为：条目内并列两说 + 各自出处，`conflicts` 字段落盘，`references/glossary.md`
   渲染成 **⚠️ 来源冲突（未裁定）** 块，并同步登记 `pending-review.md`。
   `SKILL.md` 第 5 节新增硬要求：遇到 `conflicts` 非空必须两说并列、不得自行裁定。
2. **[high] `derived`（归纳）条目缺少运行时声明要求。**
   该要求原本只写在 `CHANGELOG.md` / `pending-review.md` / `curated-terms.json`，
   而 `SKILL.md` 才是运行时主指令。现已在 `SKILL.md` 第 5 节写入：
   引用 **〔归纳〕** 条目必须说明「这是从 wiki 多页归纳的、wiki 无同名独立条目」。
3. **[high] 四个章节分片的「章节导语」块被污染。**
   根因是 PS 5.1 的 `@( … | ConvertFrom-Json )` 陷阱：`series-index.json`（22 条）被压成
   「1 个元素、而该元素是 22 元素数组」，导致 22 个系列页被当成一个对象，
   每条导语渲染成几十行（chapter-02 出现 22 行、chapter-04 出现 176 行），
   且混入大量**其他章节**的条目、部分标题为空。
   现改为「按该系列的所属任务落在哪一章投票」决定归属，并只取描述首个非空行、压平长度。
   实测结果：各章导语 = 本章系列数（0/0/1/5/8/6）。
4. **[medium] `term:term-41` 泰坦分组写「另两组」** → 补全为
   **支柱 / 命运 / 创生 / 灾厄** 四组（组名见 wiki「翁法罗斯」页小节标题），
   并补充任务内表述「三位编织法则…三位引发灾难」与 wiki 组名的对应关系。
5. **[medium] `chapter-index.md` 的 217/204 差额未解释** → 补完整账目：
   245（分类总页）= 217（任务页）+ 22（系列总览页）+ 6（模板异常）；
   217 = 204（主线，已入库）+ 13（非主线，如「宇宙均衡」试炼）。
6. **[low] glossary 条目 ID 断档** → 两条策展条目改为 `term:term-40`、`term:term-41`，
   消除「缺 term-40 / 缺 concept-01」的错觉。
7. **[low] manifest 措辞** → 统一为「人工策展归纳（derived=true）」，与 CHANGELOG 用词一致。
8. **[blocker，复验第二轮发现] `glossary.md` 里 39 条普通词条挂了空的「⚠️ 来源冲突」块。**
   根因是 PowerShell 的坑：条目对象里**没有** `conflicts` 键时，`@($e.conflicts)` 得到的是
   `@($null)`、`Count` 仍为 1，于是渲染器对全部 41 条都吐了冲突块模板，其中 39 条内容为空
   （`- 争议点：　状态：` / `- 说法 A：` / `- 说法 B：`），与 `data/*.json` 的真实状态矛盾，
   也让 `coverage` 谎报「40 条含未裁定冲突」。
   现改为按「元素是否真有 `field`」判定（`Where-Object { $_ -and $_.field }`），
   实测结果：冲突块 **1 个**（仅 `term:term-40`）、空壳 **0 个**、`coverage` 计数正确。
9. **[blocker，复验第二轮发现] 版本未递增。**
   复验时 `manifest.yaml` 仍是 `0.1.1` 而 `CHANGELOG.md` 已写 `0.1.2`，属
   `UPDATE.md` 明文禁止的「已完成 CHANGELOG、未完成版本递增」中间态。
   根因：改 `CHANGELOG.md` 时忘了同步递增生成器的 `$KBV` 常量。
   现 `$KBV = '0.1.2'`，全部分片 front-matter（11 个 `references/*.md`）与 manifest 各分片
   `version` 均为 `0.1.2`，已全库校验一致。
